# Give the model sandboxed, allowlisted file tools instead of loading the repository into the prompt

The Agent Environment is too large for the context window (the example repository is several MB of curriculum text), and its `AGENTS.md` expects the model to look things up and write task files. The model therefore gets a small fixed catalog of file tools implemented in the backend. There is no shell, no script execution and no network tool. Every call passes through `.agenthidden`, `.agentreadonly` and `.agenttools` rules that live in the repository, plus built-in protections that the repository cannot lift. Writing is enabled only by the Admin's Commit Permission, never by the repository itself. We accepted that this requires a tool-calling model and several round trips per Turn (slow on weak hardware) in exchange for an attack surface limited to path-checked file operations.
